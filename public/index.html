02 / Admin and operations API

One enrollment, one order, no matter how many jobs run

In a platform rebuild alongside an external agency, I led the admin API staff use to run the platform: 25 tickets in two months, each with integration tests. The one I'm proudest of stops two background jobs from ever creating the same order twice.

.NET 10, EF Core, SQL Server, Hangfire, Auth0, Azure

UPDATE enrollments
SET status = 'in_progress', updated_at = now()
WHERE id = @id
  AND status <> 'completed'
  AND (status <> 'in_progress'
       OR updated_at < now() - interval '15 minutes');
-- 1 row: this job owns it. 0 rows: another job does.
  1. 1A job does nothing while another holds a fresh claim.
  2. 2A claim a crashed worker left behind is taken over, and exactly one order is created.
  3. 3A failed enrollment queued twice still produces one order.
